# pi-wait

给 Pi 增加 `/wait` 命令：在 Pi 进程内暂存任务，到指定时间才把它作为正常用户消息发送给 AI。等待期间不会发起模型请求，也不会提前把任务加入 AI 上下文。

## 安装

在仓库根目录运行：

```bash
pi install ./packages/pi-wait
```

临时试用：

```bash
pi -e ./packages/pi-wait
```

安装或修改后，在已打开的 Pi 中执行 `/reload`。注意：本插件是纯内存调度，`/reload` 会清空当前待发任务；重要任务请先让它到点发送，或重新设置。

## 使用

先设置时间，再输入任务：

```text
/wait 30m
请检查项目中的测试失败并修复
```

第一条命令只让插件等待下一条**普通输入**。第二条输入会被插件截获并保存在当前 Pi 会话中，不会立即交给 AI；30 分钟后才会真正发送。

Pi 会先分发 `/` 开头的扩展命令，再触发普通输入事件。因此，定时执行斜杠命令时必须使用一行形式，不能把它作为两步模式的第二条输入：

```text
/wait 30m -- /review src/index.ts
```

该斜杠命令只会在到期后展开和执行。

也可以一行完成：

```text
/wait 2小时 -- 运行测试并修复失败
/wait 09:30 -- 检查 CI 状态
/wait 2026-08-31 08:00 -- 完成剩余任务
```

支持的时间形式：

- 相对时间：`30s`、`15m`、`2h`、`1h30m`、`2小时`、`1天`
- 本地时钟：`09:30`；如果今天已经过了该时刻，则按明天处理
- 本地日期时间：`2026-08-31 09:30`
- 带时区的 ISO 时间：`2026-08-31T09:30:00+08:00`

管理任务：

```text
/wait list
/wait cancel
/wait cancel <任务ID或唯一前缀>
```

- `/wait cancel` 取消“等待下一条输入”的状态。
- `/wait cancel <ID>` 取消一个已经保存的定时任务。

## 生命周期

任务只保存在当前 Pi 进程的内存中：

- Pi 保持运行时，任务会按时发送。
- `/reload`、切换/fork/clone 会话或退出 Pi 时，待发任务会被清除，不会误发到其他会话。
- Pi 完全关闭期间没有后台调度能力；因此它不是操作系统级任务计划器。
- 到点时任务会作为 follow-up 交给 Pi；AI 正忙时，它会等当前工作结束。
- 任务不会写入 Pi session 文件，也不会进入模型上下文；因此不存在提前把任务发送给 AI 的路径，但进程退出后也无法恢复。

终端页脚会显示等待输入状态，或待发送任务数量和最近到期时间。

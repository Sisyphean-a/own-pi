# 顾问上下文

## 作用域

- 上下文：`pi-advisor`
- 实现包：`pi-advisor`
- 入口与证据：`packages/pi-advisor/extensions/index.ts`、`src/advisor.ts`、`src/advisor-config.ts`、`src/advisor-runner.ts`、`src/advisor-read.ts`、`src/advisor-messages.ts`、`src/advisor-signals.ts` 与 `README.md`

## 术语

- **执行模型**：当前 Pi agent，负责实际探索、编码、运行命令和验证。
- **顾问模型**：由 advisor 配置选择的顾问模型，接收精选上下文，可只读调查文件后返回战略建议。
- **跳过规则**：`skipWhenCurrentModel` 中匹配当前执行模型的裸模型 ID、精确 `provider/model` 或 `*` glob；命中后不调用顾问。
- **agent run**：一次从 `agent_start` 到 `agent_end` 的执行周期。
- **验证命令**：以测试、检查、lint、typecheck 或 build 等已识别命令开头的 Bash 管道段。

## 稳定规则

- 顾问是按需调用的第二意见，不替代执行模型；只获得 `read` 文件读取能力，不获得命令执行、文件修改或其他工具，最后返回 `On track`、`Course-correct` 或 `Not done yet` 及最多 5 条行动项。
- 每次咨询必须提出一个具体决策问题；执行者补充的约束、方案和假设标为未验证观点，不代替工具原文。工具说明指导执行者提供相关路径、约束与已有执行结果，顾问应先自行读取缺失的文件证据再判断，不能仅因初始上下文不足而退回泛泛建议。运行测试和外部状态等只读无法取得的证据才交回执行者；没有新证据或决策变化时不重复咨询。
- 上下文保留用户任务 framing 和最新证据；assistant 只保留文本，超限时省略中间消息。工具活动摘要不证明代码内容或测试成功；证据不足时顾问必须指出缺口，不能为未见实现背书，咨询不等同于独立审查。
- 原始工具证据由插件按固定规则从当前 run 的有限窗口采样，优先保留失败、验证、修改和读取，保留来源与截断提示；不由执行者单独挑选，也不因此新增调查请求。采样仍可能遗漏反证，不能保证模型不受提示注入或确认偏误影响。
- 历史工具原文自动转发由 `includeToolEvidence` 显式开启、默认关闭，原因是源码和日志可能含敏感信息；它不禁用顾问主动 read，也不是全面隔离。会话/系统提示/短摘要和主动读取文本仍可外发，不承诺自动脱敏。片段是数据而非指令，执行模型仍负责核对建议。
- 顾问读取必须复用执行者的 read 通道及权限钩子，不绕过主机拦截；读取范围沿用执行者权限，不另承诺工作区沙箱。主机缺少可调用 read 时拒绝咨询，而非静默退回无工具模式。
- 执行模型的工具活动用于顾问上下文和阶段判断；顾问的只读调用纳入主机嵌套追踪，不注册代码修改/验证状态栏提醒。
- 只有真实进入模型调用的咨询计入每轮调用上限；模型不存在、认证失败、无上下文或其他前置失败不消耗额度。
- `skipWhenCurrentModel` 默认为空以保持原行为；命中时在模型选择事件中从 active tools 隐藏 advisor，执行层仍二次拦截旧调用，并且 `/advisor ask` 不发送咨询请求。
- 模型强弱没有跨 provider 的可靠排序；需要跳过更强模型时由用户显式加入完整模型 key 或 glob，避免误判。
- 顾问模型配置和调用预算属于 advisor 自身；项目调查、文件修改和执行顾问建议均由执行模型控制，单次咨询允许有限多轮只读调查，对读取次数和文本体积设上限，预算内预留无工具的最终判断；失败请求不自动重试，并行咨询共享每轮咨询预算。
- `timeoutMs` 触发整次咨询的模型请求和读取取消，不覆盖认证和准备，也不保证 provider 精确按时结束或停止计费；超时、取消、截断和模型错误不能伪装为成功，不自动降级推理或换模型。
- 已进入请求的咨询保留耗时、停止原因、模型请求数和读取次数，用量累计所有新响应而非仅最终回答，包括失败和空响应。任一响应缺项或请求没有最终用量时，对应总量保持未知，已完成响应仍各自发布；缺失计数不是零，provider 未报告时不能保证恢复账单用量。计量通知沿用 [model-usage](model-usage.md)，不另定义跨包协议。

## 非目标

本上下文不负责自动决定何时修改代码或执行顾问建议，也不提供顾问自动运行命令的流程。

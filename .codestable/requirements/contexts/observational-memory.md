# 观察式记忆上下文

## 作用域

- 上下文：`observational-memory`
- 实现包：`pi-observational-memory`
- 入口与证据：`packages/pi-observational-memory/src/index.ts`、`src/runtime.ts`、`src/hooks/`、`src/agents/`、`src/session-ledger/`、`README.md`

## 术语

- **观察**：带时间、重要度和源条目 id 的会话事实记录，是压缩前的证据层。
- **反思**：由观察支撑、带明确作用域的当前持久结论。
- **撤回**：有明确变化证据时停用旧反思，保留原文、原因及来源；可与替代结论原子提交。
- **精简**：按留存替代证据移除冗余、已被取代或已解决的活跃观察；账本历史仍可召回。
- **处理回执**：确认本次提供的全部源片段已审阅，允许零观察；与事实来源证明分离。
- **会话代次**：后台任务启动时捕获的会话标识；会话替换、重载或退出后失效。

## 稳定规则

- 面向用户的通知、命令描述与输出、状态与查看内容、worker 提示词统一使用简体中文；代码、路径、命令、标识符和错误消息保留原文。
- 后台 worker 按进度或观察池压力启动；距离主动压缩阈值不足一轮观察预算且有未处理历史时，优先连续处理固定快照，暂缓反思与精简，不无限追逐新消息。观察池达到维护压力时允许反思/精简插入，避免追赶耗尽后续输入预算；追上后恢复维护，阶段启动阈值不变。精简不要求同轮新增反思；预算压力不构成事实失效或强制删除依据。失败不得阻塞 Pi 主回合，也不得伪造成功。
- 会话替换（new/resume/fork）、重载或退出时，Pi 先触发 `session_shutdown` 再让旧 ctx/pi 失效；扩展必须先用会话代次作废在途后台任务，之后不得再触碰旧 ctx/pi；stale-ctx 错误按正常取消处理，不作为失败提示用户。
- 记忆摘要只使用已提交账本，不等待 worker。达到主动阈值后，正常回合边界可直接折叠完整处理的旧前缀，未处理的新消息原样保留；遵守宿主近期保留预算和工具配对，切点不前进或估算无缩减收益时不压缩。失败、取消、长度截断及其他扩展已有提案时不抢先折叠。Pi 请求压缩时仍仅在其待移除历史完整覆盖且有可渲染记忆时接管；覆盖不足、摘要为空或用户指定重点时交给原生摘要器，避免旧记忆吞掉新约束。
- `coversUpToId` 不是来源或完整处理证明。完整源覆盖须有连续片段的处理回执；超长源续读中部，零观察可推进游标，失败或缺回执不提交整批结果。
- 观察来源由 `sourceEntryIds` 表达，反思来源由 `supportingObservationIds` 表达；引用数量不是安全精简的证据。不同源上的同文重申是独立事件，不复用旧精简身份。
- 同一主题与作用域有明确纠正、取代或失效证据时，撤回旧反思；提问、时间流逝或未再次提及不构成撤回理由。每次记忆压缩应用当前结论和撤回，不延迟到池达到上限。
- 精简须给出原因及全部留存替代证据，仅 low 级例行回执可无替代证据；替代证据失效时恢复原观察。撤回和精简都不删除历史召回通道。
- Worker 的既有记忆、源片段、系统与工具声明及输出预留共同占用输入预算；超预算显式失败，不靠截掉旧记忆伪装成功。
- worker 的 LLM 流因瞬态传输或服务端失败结束时，可重跑整个 worker 调用；缺回执、校验失败、预算超限、额度耗尽与取消除外。重跑不得产生重复或部分条目：worker 工具只修改本次调用内的内存状态，账本提交发生在调用成功之后。
- 覆盖进度的原始 token 计量是增量水位：只累计覆盖点之后新增的源条目，覆盖标记推进时才从新标记重新累计；真实上下文增量仍以 provider 上报的 usage 为基准。阶段到期判断不得要求逐轮重算整本账本。
- 记忆按当前分支折叠重建；兼容读取旧 V3，不把旧水位当新处理回执，不改写或迁移已有会话。V2 设置和条目仍不迁移；旧版本不支持新增撤回语义，回退应新建会话。

## 非目标

本上下文不替代 Pi 的会话存储、原生压缩、模型认证或失败恢复策略；它消费 Pi 的会话事件、模型与 UI seam，负责记忆的提取、折叠、渲染、召回及基于已准备记忆的主动压缩。
